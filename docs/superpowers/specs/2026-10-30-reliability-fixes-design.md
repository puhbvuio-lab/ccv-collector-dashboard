# CCV 工具可靠性修复设计

## 意图

修复首轮审查确认的运行环境和任务生命周期风险，使新环境安装、任务创建、任务删除、状态恢复与 Excel 导出具备可重复验证的行为。

## 范围

- 为同一秒创建的同目标任务生成唯一 ID，避免覆盖任务和数据目录。
- 删除运行中任务时，只有工作线程确认结束后才移除任务记录及可选数据；超时则保留任务并记录失败状态。
- 加载持久化任务时，把没有本进程工作线程的 `running` 视为待恢复状态，再由服务显式启动并持久化实际状态。
- 补齐 `openpyxl` 运行依赖；把 Playwright 与报告构建器仍视为可选运行时，并改善文档说明。
- 修复 `监测20分钟.bat` 的硬编码 Python 路径。
- 建立最小自动化测试集。

## 非目标

- 不改变 Twitch/YouTube API 采样逻辑、数据格式或看板外观。
- 不把 `@oai/artifact-tool` 加入 npm 依赖，因为它不是公共项目运行时的稳定依赖；内置轻量 Excel 导出继续使用 `openpyxl`。
- 不清理现有采集数据或自动改写历史任务。

## 方案

采用原地、小范围修复：在 `TaskManager` 中增加唯一 ID 分配和安全删除状态转换，用 `unittest` 覆盖行为，并补齐依赖与脚本。相比重构任务调度器或引入数据库，此方案对现有用户数据和 API 兼容性风险最低。

## 成功标准

测试可证明 ID 不碰撞、活线程超时不会被清除、退出线程可以安全删除、陈旧状态可识别、Excel 依赖已声明；Python/Node 语法检查和完整测试套件通过。
